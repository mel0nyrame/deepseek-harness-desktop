# DSH Desktop

English | [中文](README.zh.md)

`@deepseek-ai/dsh-desktop` is the Electron application package for DSH Desktop in the `deepseek-harness-desktop` repository. Electron main supervises one dedicated application-scoped DSH child carrying the [`desktop` profile](../../apps/cli/README.md) (base + Web product + desktop overlay with every browser transport row disabled), a context-isolated preload bridge carries the existing Connection protocol, and the packaged React client renders locally. No browser-facing HTTP listener participates.

## Development

`pnpm run dev:desktop` (repository root) builds the workspace and launches Electron main in development: the DSH child boots from the source tree through `apps/cli/lib/bin.js` on the ambient Node runtime, the Web frontend is served from the built `dist`, and quitting terminates the owned process tree. The keyless development interaction-parity scenario (`apps/desktop/tests/real-composition.e2e.ts`) drives the same surface without a window: one durable Workspace, three Sessions whose replayed turns cover the ordered terminal stream, a question answered over the carrier, and a sandbox-escalation approval answered over the carrier, then reconstruction of every model-visible input from the durable Session logs.

## Carrier security and lifecycle

The `BrowserWindow` keeps `contextIsolation: true`, `nodeIntegration: false`, and `sandbox: true`. The preload exposes only boot, unary request/cancellation, stream subscription/cancellation, and stream-notification operations. Electron main accepts them only from exact `dsh://app` frames and validates every payload; child-to-main messages and main-to-preload lifecycle notifications are validated again before correlation or renderer delivery, and ready-handshake bundle paths must resolve to real `.js` files beneath the configured development or packaged runtime root. The existing Connection zod schemas then validate RPC envelopes and mux/Host frames before client dispatch.

Each renderer subscription retains at most 256 parsed frames. The consuming client acknowledges every delivered frame only after it has taken it (lifecycle open/end events are acknowledged on arrival), and Electron main forwards that acknowledgement to the child while bounding each stream's in-flight and queued relay state — the frame bound is a safety net, and real renderer consumption paces the ordered source. Overflow or a duplicate open notification cancels the physical subscription and emits an ordered error/end closure; renderer overflow clears its queue, cancels the physical subscription, and terminates the iterator with an error. Caller cancellation discards queued frames immediately. The child stream pump awaits each IPC send callback plus the per-frame acknowledgement before reading the next frame, so native-channel backpressure pauses the ordered source instead of reclassifying an accepted message as lost. Electron main cancels renderer-owned requests and streams on main-frame reload/navigation, renderer crash, or renderer destruction; child disconnect/exit/error closes every active request and stream, while application quit or startup failure stops and joins the child.

## Native desktop actions

The renderer keeps the existing task-level workspace and path-opening APIs; it receives no dialog, shell, filesystem, Node.js, or general Electron primitive. Inside the DSH child, the desktop overlay provides the `directoryPicker` and `nativePathOpener` services and sends only the closed `pick-directory` and `open-path` reverse requests to Electron main. Main validates the request and absolute path, uses `dialog` or `shell.openPath`, and owns the actionable native failure dialog. Request cancellation propagates from the renderer through the Host carrier to main; child disconnect, generation removal, and application shutdown abort pending operations and ignore late native settlements.

## Host recovery

`DesktopLifecycle` owns one explicit state machine over the supervised Host: `starting`, `running`, `recovering`, `failed`, `stopping`, and `stopped`. Startup timeout or configuration failure lands on the status page with the child's recent stderr tail and Restart/Quit actions; an unexpected exit of a running Host triggers exactly one automatic restart, and a failed recovery returns to the failed state with the same actions. `restart()` is available only from `failed`, so a repaired profile can be restarted without relaunching the application. While the Host runs, the supervisor refreshes a pre-exit ownership snapshot so crash recovery can still identify descendants that later reparent into their own process groups, including PTY session leaders. All quit paths share one stop owner that requests graceful shutdown, escalates through SIGKILL, sweeps the observable process tree, and reports an actionable `cleanup-incomplete` failure with surviving pids instead of claiming success while any owned process remains; an incomplete cleanup blocks Restart so a replacement generation cannot make quit forget the previous tree.

## Packaging (macOS)

`pnpm --filter @deepseek-ai/dsh-desktop run package` produces an ad-hoc signed application bundle and dmg for the host architecture under `apps/desktop/dist/` through six stages ([`scripts/package.ts`](scripts/package.ts)):

1. **Closure** — `pnpm run verify-runtime-closure` proves this package's dependency manifest supplies every required workspace peer.
2. **Deploy** — a pnpm legacy deploy materializes the production runtime closure (the `dsh` CLI, every in-box plugin's built `lib`, the Web frontend `dist`, node-pty, and the keyless replay provider) into a symlink-free staging directory.
3. **Electron restore** — when the pinned Electron distribution is missing (fresh installs fetch it through Electron's reviewed postinstall, `allowBuilds`), the package's own install script restores it before rebuild and validation.
4. **Native rebuild** — node-pty is rebuilt against the pinned Electron version's ABI (`@electron/rebuild`), then validated by loading it inside the Electron binary; the macOS `spawn-helper` is staged beside the rebuilt addon with its executable bit.
5. **Bundle** — electron-builder ([`electron-builder.yml`](electron-builder.yml)) assembles and ad-hoc signs (`identity: '-'`, no Apple credentials) the `.app` and the `.dmg`: the asar carries only `lib/main.js` and the sandboxed preload, while the runtime closure ships as real files under `Contents/Resources/runtime/`. The application icon is the official DeepSeek Harness fish logo on a light rounded tile: [`build/icon.svg`](build/icon.svg) is the committed source, [`scripts/icon.ts`](scripts/icon.ts) rasterizes it to `build/icon.png`, and electron-builder converts that PNG into the bundle's `icon.icns`.
6. **Evidence** — every produced artifact passes [`scripts/artifact-evidence.ts`](scripts/artifact-evidence.ts): `codesign --verify --deep --strict` proves the signature, `spctl --assess` records the Gatekeeper verdict, `hdiutil verify` checks the dmg image, and each `.app` must carry `Contents/Resources/icon.icns` named by `CFBundleIconFile` (the default Electron icon fails the gate).

The installed application starts without a system Node.js or DSH CLI: Electron main forks the application binary itself as the DSH child (`ELECTRON_RUN_AS_NODE`), resolves the CLI, Web dist, and PTY helper from `Contents/Resources/runtime`, and hands the child its user-data directory as the working directory ([`src/packaged-runtime.ts`](src/packaged-runtime.ts) owns this layout). Native modules and the PTY helper therefore never sit inside an archive. The harness home stays the shared `~/.dsh`, so the packaged app and the CLI see the same sessions, profiles, and configuration.

The ad-hoc signature has no identity behind it. Gatekeeper assesses only quarantine-flagged launches, so a locally built artifact opens unassessed while `spctl --assess` itself rejects every ad-hoc signature — the packaging pipeline records that verdict as evidence, and it becomes a hard gate once a Developer ID identity signs the artifacts. A downloaded copy carries `com.apple.quarantine`, shows the unidentified-developer gate, and needs the one-time right-click → Open (Homebrew cask delivery strips quarantine instead). Removing that gate for downloads requires Developer ID signing and notarization — paid Apple Developer Program credentials; `electron-builder.yml` documents the fields to fill when they exist. The packaging script builds the host architecture only, because node-pty rebuilds against the host ABI; the x64 artifact comes from the [`desktop-release.yml`](../../.github/workflows/desktop-release.yml) CI matrix (`macos-26-intel`).

## Native macOS window

The macOS `BrowserWindow` uses `hiddenInset` title-bar chrome, fixed inset traffic lights, a transparent client surface, and Electron's AppKit-backed `under-window` vibrancy with `visualEffectState: followWindow`. The compact frame removes the synthetic full-width title strip: the client root fills the window, and on macOS the sidebar's first row shares the native traffic-light region — the sidebar toggle sits to the right of the native light group with a 16-pixel gap — while the DeepSeek Harness wordmark occupies the following row. The compact header is a macOS-only presentation; Web and other desktop platforms keep the previous sidebar shell. The topmost conversation header, sidebar control and wordmark rows, and modal title rows drag the native window; links, form controls, buttons, editable content, the sidebar workspace list, the conversation transcript, the composer, and modal bodies remain interactive no-drag regions. In native full screen AppKit auto-hides the traffic lights and reveals them again when the pointer reaches the screen top; the application does not force their visibility. The sidebar control and wordmark rows move to the sidebar's left content inset without vertically reflowing the remaining sidebar content. Collapsing the sidebar resolves to a zero-width track: the sidebar material, contents, resize handle, and divider are gone, the conversation reclaims the full width, and the frame's reveal control — placed beside the traffic lights in windowed mode and at the left content inset in full screen — stays outside the sidebar subtree; the conversation header clears only that top-left chrome cluster, aligns its title with the reveal control, and moves the Chat / Trajectory row and divider up with it, never retaining the former sidebar width. Expanding restores the last usable sidebar width.

The expanded macOS sidebar uses one continuous native material while the conversation and details surfaces remain opaque. Both light and dark glass variants leave the sidebar transparent over the existing AppKit-backed material; the context-isolated preload bridge mirrors the application preference to Electron's validated main-process IPC, and `nativeTheme.themeSource` selects the matching native Light, Dark, or System appearance. The dark `under-window` material path is unchanged. New Session and selected-session treatments use readable translucent semantic overlays on both glass variants. General → Appearance exposes the default-enabled `Sidebar glass effect` switch only when the macOS Host namespace is present and writable; an interaction changes the material immediately and persists `ui-sidebar-glass-macos.enabled` through the Host, including across application restart. Reduce Transparency forces the matching opaque sidebar fallback without rewriting the saved switch, and restoring transparency reveals glass again when the preference remains enabled. Supported Electron APIs satisfy the layout and accessibility contract, so the application includes no custom native visual-effect addon.

## Packaged acceptance

`apps/desktop/tests/packaged-smoke.e2e.ts` launches the installed bundle in nine modes. `--inspect-native-window` creates a real `BrowserWindow` and reports the configured title-bar, traffic-light, transparency, vibrancy, focus, drag-region, appearance, and reduced-transparency state for automated assertions. `--accept-native-window` opens a visible window over the assembled renderer and asserts the active → inactive → active focus transitions, minimize/restore, native full-screen entry/exit with sidebar-control alignment, the windowed control-row inset past the traffic lights, the synthetic drag-region input attempt, the compact full-height layout with no content obstruction, computed drag/no-drag regions, and the keyboard path into the real composer. It then drags the sidebar to a custom width, collapses it, and asserts the zero-width grid track, the reclaimed conversation surface, the reveal control beside the traffic lights, the collapsed-header clearance and top inset, full-screen reveal alignment at the left content inset, and the restore of the exact dragged width. `--accept-native-window-drag --smoke-replay <file>` is an opt-in OS-pointer lane selected with `DSH_DESKTOP_NATIVE_DRAG_REQUIRED=1`: an external CoreGraphics driver drags the onboarding title, expanded-sidebar control row, and collapsed conversation header and verifies each move through the native `BrowserWindow` bounds, then verifies the composer stays fixed and receives focus. This lane hard-fails when macOS Accessibility permission is unavailable. `--accept-sidebar-glass --sidebar-glass-phase <default-off|reopen-on|reopen-enabled>` runs three launches against one explicit test home: it asserts default-on glass with opaque content surfaces, immediate disable and Host persistence, restart recovery of the disabled state, re-enable, transparent light/dark glass, matching `nativeTheme.themeSource` values read from Electron main, the Reduce Transparency opaque fallback without preference loss, and a final restart with native Light glass still enabled. `--record-native-window --smoke-replay <file> [--smoke-child-replay <file> …]` plus `DSH_DESKTOP_FRAMES_DIR` records truthful renderer frames of launch, the assembled native drag surface, focus transitions, the drag-region attempt, keyboard operation, minimize/restore, native full-screen transition (expanded and collapsed), the zero-width collapsed sidebar, the revealed sidebar, settled-Session collapsed frames with the title, tabs, and divider, light/dark appearance, the replayed terminal turn, and the question and approval turns answered through the assembled question composer and approval panel, then restores `nativeTheme.themeSource` to its entry value. `--record-native-actions` plus `DSH_DESKTOP_FRAMES_DIR` keeps the real installed window, preload, ApiProxy, reverse child IPC, Workspace adoption, and Session navigation while substituting deterministic dialog/shell primitives; it records the adopted Workspace plus structured success and actionable-failure evidence because renderer capture cannot include native dialogs. `--record-recovery --smoke-replay <file>` plus `DSH_DESKTOP_FRAMES_DIR` seeds a broken desktop profile, records truthful renderer frames of the failed status page, the controlled restart, and the recovered assembled UI through the replayed terminal turn, and then quits quiescent. `--smoke --smoke-replay <file> [--smoke-child-replay <file> …]` asserts the full keyless interaction-parity scenario — durable Workspace creation and idempotent reopen, a terminal-backed `echo TERMINAL_OK` tool turn with ordered streamed events, a question turn and a sandbox-escalation approval turn both answered over the carrier, reconstruction of every model-visible input from the durable Session logs, no TCP listener, and quiescent quit — plus the absence of surviving owned processes. A second launch with `--smoke-reopen --smoke-home <dir>` boots the same durable home and asserts the Workspace and all three Sessions reconstruct from the existing persistence with no model call. The suite self-skips when the bundle is absent; the macOS CI job packages first and sets `DSH_DESKTOP_SMOKE_REQUIRED=1`, which turns absence into a hard failure. Every journey mode disables hardware acceleration before `ready`: CI macOS runners expose no reliable GPU, a transient command-buffer failure wedges the renderer's script channel and hangs the journeys' `executeJavaScript` waits, and software compositing keeps each journey's paints and `capturePage` frames deterministic on any host.

## Limitations

- Artifacts ship ad-hoc signed and un-notarized: a downloaded copy needs the one-time right-click → Open until Developer ID signing and notarization (paid Apple Developer Program) are wired in.
- `--smoke` refuses to run without an explicit `DSH_HOME`, so it can never touch the machine owner's real `~/.dsh`.
- Startup recovery does not repair the profile itself: `restart()` retries the same configuration, so a broken profile must be repaired before Restart can reach the running phase.
- The crash-recovery ownership snapshot refreshes once per second, so a descendant created and orphaned entirely between refreshes can only be swept when its process group still identifies it.
- `capturePage()` sees renderer pixels only: recorded frames exclude native traffic-light glyphs, and synthetic input cannot prove native window movement. The opt-in CoreGraphics acceptance lane supplies that OS-pointer evidence; a machine with screen-recording permission can replace the renderer frames with an OS-level capture without changing the assertions.
- **No programmatic dialog dismissal** — Electron's `dialog.showOpenDialog` has no close or abort API, so request cancellation settles the operation logically and ignores late settlements while a dialog already on screen stays until the user dismisses it.
