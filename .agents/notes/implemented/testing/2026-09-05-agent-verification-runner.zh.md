# Agent Note: 串行化的代理验证运行器

Status: implemented

[English](2026-09-05-agent-verification-runner.md) | 中文

## 问题

仓库验证横跨工作区检查、macOS 打包和安装产物测试。代理此前必须自行还原这组顺序，并逐条调用命令。已有的 `apps/desktop/dist` 产物还会让工作区 Vitest 发现逻辑纳入打包后的原生 UI 测试，因此源码测试可能与打包后的 Electron 运行重叠，并争用 macOS 全屏状态。冗长的命令输出随后会掩盖具体失败的门禁，以及完整日志所在位置。

## 决策

`pnpm run test:agent` 是可发现的代理验证入口。默认的 `all` 预设依次串行运行工作区检查、打包、安装产物验证和最终 diff 检查。工作区步骤会暂时隔离已有的 `apps/desktop/dist` 目录，并在命令结束后恢复它，从而避免源码与打包后的原生 UI 门禁重叠运行。

运行器还通过 `pnpm run test:agent -- --help` 提供较小的 `workspace`、`package`、`focused` 和 `quick` 预设。它输出稳定的 `AGENT_CHECK` 状态记录、长步骤的周期性心跳、`.artifacts/agent-check/` 下每个步骤的一份完整日志，以及终端中的有界失败尾部。根 `AGENTS.md` 只把后续会话指向帮助命令，不复制参数契约。

## 验证

`tests/agent-check.test.ts` 锁定参数校验以及默认与 focused 预设的精确计划。一次 focused 运行器调用覆盖构建、聚焦 Vitest 执行、日志和 diff 校验。默认调用覆盖完整的工作区到安装产物串行路径，以及打包产物隔离边界。

## 已考虑的替代方案

**把所有底层命令复制进 `AGENTS.md`。** 命令列表容易被忽略，也会随门禁变化而漂移，并且无法提供串行化、结构化结果或持久日志。

**让所有 Vitest 执行全局串行。** 这会拖慢无关测试并改变普通测试套件的语义，而原生 UI 冲突只在打包产物存在时才需要处理。

**使用直接继承全部输出的 shell 脚本。** 这种方式很紧凑，但不能为代理提供稳定的结果记录、逐步骤日志、失败尾部和类型化参数校验；补齐这些能力又会依赖 shell 特有行为重新实现。

## 后果

代理可以从一个命令发现并运行合适的验证计划，类似 CI 的原生 UI 门禁也以确定顺序执行。完整输出会占用被忽略的产物存储；完整 `all` 运行仍然有意保持昂贵，因为它会打包并启动安装后的应用。临时移动的打包产物会在正常完成和命令失败时恢复；若进程被外部强制终止，可能留下名称明确的 hold 目录，需要人工恢复。
